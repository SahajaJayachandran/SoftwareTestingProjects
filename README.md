# 🧪 Manual Testing Project

Welcome to the **Manual Testing Project** repository! This project contains a complete test plan and a collection of test cases designed to validate the functionality and quality of the application under test (AUT). It is ideal for QA teams, testing professionals, and learners aiming to understand structured manual testing workflows.

## 🧭 Project Overview

This manual testing project is designed to simulate a real-world QA process. It follows structured testing practices, including test planning, test case creation, execution, defect logging, and reporting.

---

## 📋 Test Plan

Located in the `Test_Plan/` directory, the test plan outlines:

- **Scope & Objectives**
- **Testing Types (Functional, Regression, etc.)**
- **Test Strategy & Approach**
- **Test Deliverables**
- **Resource & Environment Needs**
- **Schedule & Milestones**

---

## ✅ Test Cases

Found in the `Test_Cases/` directory. Each test case includes:

- **Test Case ID**
- **Title/Description**
- **Preconditions**
- **Test Steps**
- **Expected Result**
- **Actual Result**
- **Status (Pass/Fail)**
- **Comments**

Test cases are categorized by feature/module for clarity.

---

## 🐞 Bug Reports

(Optional) Located in the `Bug_Reports/` folder, this section includes:

- **Bug ID**
- **Summary**
- **Severity & Priority**
- **Steps to Reproduce**
- **Expected vs Actual Results**
- **Status**

## 📊 Test Execution Results

Located in the `Test_Results/` folder. Includes:

- Test summary reports
- Pass/fail statistics
- Notes from testers

## 🛠 Tools Used

- Microsoft Excel / Google Sheets (for test documentation)
- Jira / Bugzilla (optional – for issue tracking)
- Manual Testing Checklists

---

  ## 🚀 How to Use
  
  1. Clone the repository.
  2. Review the `Test_Plan/` to understand the scope.
  3. Execute test cases in `Test_Cases/` against your AUT.
  4. Log bugs in `Bug_Reports/` if any issues are found.
  5. Record your execution results in `Test_Results/`.
